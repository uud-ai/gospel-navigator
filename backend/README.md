# backend/

Облачная функция чата для «Благовеста». Написана с нуля (исходник, на
который ссылались сборочные скрипты, был утерян и не восстанавливается —
см. историю в корневом README).

## Что делает

1. Проверяет заголовок `X-App-Token` и простой rate limit (в памяти процесса,
   не распределённый — см. комментарий в коде).
2. Считает эмбеддинг последнего сообщения пользователя (proxyapi.ru,
   `text-embedding-3-small`, 512 измерений — как и у данных в `data/`).
3. Находит самые похожие стихи Евангелия и фрагменты толкования Феофилакта
   (косинусное сходство, без внешней векторной БД).
4. Собирает их в контекстное сообщение и отправляет вместе с историей чата
   в `proxyapi.ru/chat/completions` (модель — `CHAT_MODEL`, по умолчанию
   `gpt-4o-mini`).
5. Проверяет ссылки на Евангелие в ответе против `data/bible.json`; если
   ссылка не находится — не блокирует ответ, а приписывает предупреждение.
   Ссылки на книги НЗ вне Евангелий не проверяются (текста нет).

## Статус

**Системный промт — заглушка** (`SYSTEM_PROMPT_PLACEHOLDER` в коде).
Настоящий текст — богословский контент, требует отдельного утверждения
автором проекта и не должен попадать в код до этого.

**Не задеплоено и не протестировано вживую** — нет доступа к Yandex Cloud
аккаунту автора. Перед первым запуском:

- создать функцию в Yandex Cloud (runtime Node.js 18+, entrypoint
  `function.handler`), залить `function.js` + `package.json`;
- задать переменные окружения из `.env.example`;
- разместить `data/*.json` там, куда указывает `DATA_BASE_URL`, с публичным
  доступом на чтение;
- подставить реальный системный промт вместо заглушки — после утверждения;
- проверить вживую хотя бы один запрос из `index.html`.

## Сознательные упрощения (chisle-пометки в коде)

- Rate limit — in-memory, сбрасывается при каждом холодном старте и не
  работает между разными инстансами функции. Если понадобится настоящий
  лимит — нужен внешний стор (Redis/YDB), не память процесса.
- CORS — `Access-Control-Allow-Origin: *`. Можно сузить до конкретных
  доменов, если понадобится.
- Поиск релевантных фрагментов — полный перебор (brute-force cosine) по
  ~7500 векторам на каждый запрос. Для текущего объёма данных это быстро;
  если данные вырастут на порядок — понадобится приближённый поиск (ANN).
